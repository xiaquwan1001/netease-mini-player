## 5. 顺带做的实事(代码, 非文档)

发现并修掉一个**真 bug**(不是环境问题): Linux 上钥匙串 collection 被锁时,
`SecretServiceStore::available()` 走 zbus 同步调用, 会一直等解锁提示(无桌面会话 ⇒ 永不返回),
而它被 `credential_store::open_backend()` 在**启动路径**上同步调用 ⇒ 应用启动可能直接挂死。

- 实测(修前): `cargo test -p ncm-service credential_keyring::tests::available_is_cached_and_never_panics`
  **>70s 不返回**(用 `timeout -k 5 70` 强杀); 全量 `cargo test` 与 `flutter test`(frb_smoke_test 的 setUpAll)
  同样卡在同一处。根因证据: `busctl --user call ... Collection.Locked` = `true`(default alias = `login`, 已锁)。
- 修法: `probe_with_timeout(PROBE_TIMEOUT = 2s, probe_secret_service)` —— 探测在独立线程跑, 主线程
  `recv_timeout`; 超时按 `Unavailable` 处理, 上层照旧回落「用户同意的 0600 明文」, 语义不变。
  探测结果仍进 `OnceLock` 缓存(超时后本进程不再重试)。
- 修后实测: 同一条测试 **8 例 / 2.0s 全绿**(2s = 一次超时); 全量 `cargo test` **287 passed / 0 failed**(修前该套跑不完)。
